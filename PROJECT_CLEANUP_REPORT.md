## 23. REMAINING WARNINGS

**WARNING 1 — Hybrid JSON + PostgreSQL persistence in scraper_manager.py**
`scraper_manager.py` maintains both a JSON file store (`data/*.json`) AND calls `JobService`/`LeadService`/`DatasetService` (PostgreSQL). These two stores may drift out of sync over time. The JSON files were added to `.gitignore` during this cleanup to prevent accidental commits of ephemeral runtime state.

**WARNING 2 — Frontend mock layer is the initial data source**
`DataOpsContext` initializes `leads`, `datasets`, `jobs`, `activities`, and `departments` from mock TypeScript files. When the backend is healthy, it supplements (not replaces) these with live API data. This means the frontend always starts with mock data visible, even if the DB is empty.

**WARNING 3 — No authentication enforced**
`isLoggedIn` is hardcoded `true` in `App.tsx`. `AuthContext` always returns `isAuthenticated: true`. The `Login.tsx` page renders but has no functional login gate. This application must not be exposed on a public network without authentication.

**WARNING 4 — agent.service.ts serves mock sessions**
The frontend's `agent.service.ts` creates mock session data (4 pre-seeded sessions) that are loaded into `DataOpsContext`. New sessions created via the chat UI are stored in memory only — they do not persist across page refreshes.

**WARNING 5 — QueryParser is rule-based, not LLM-powered**
`agents/query/parser.py` uses regex and keyword matching. Complex or ambiguous user requests may be misclassified. No LLM API is called anywhere in the agent pipeline.
